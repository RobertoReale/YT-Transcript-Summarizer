+export async function initPrompts() {
+  try {
+    const { customTemplates } = await chrome.storage.local.get('customTemplates');
+    if (!customTemplates) return;
+    
+    for (const lang of Object.keys(customTemplates)) {
+      if (!PROMPTS[lang]) continue;
+      for (const fmt of Object.keys(customTemplates[lang])) {
+        if (!PROMPTS[lang][fmt]) continue;
+        for (const len of Object.keys(customTemplates[lang][fmt])) {
+          if (PROMPTS[lang][fmt][len] !== undefined) {
+            PROMPTS[lang][fmt][len] = customTemplates[lang][fmt][len];
+          }
+        }
+      }
+    }
+  } catch (e) {
+    console.warn("Failed to load custom prompt templates", e);
+  }
+}

    web_extension v10.20.0: timestamps in summaries, five paste/split fixes
    
    Timestamps (new). All three timedtext parsers already read the cue start time
    for the coverage check and then threw it away, so a summary could never point at
    a moment in the video. The transcript now carries [m:ss] anchors every 30 s —
    one per cue would add ~120k chars to a 2 h video and eat the composer budget the
    split exists to protect — the model is told to cite them, but only when the
    transcript really has them, and the .md turns them into links that jump.
    The instruction is appended at send time rather than folded into PROMPTS:
    isPreset() compares stored prompts against those strings, so editing one would
    freeze every existing user prompt as "custom" forever.
    
    Fixes:
    
    P  "1 part" on Gemini silently became N parts, and whether a merge followed was
       decided by a checkbox the UI hides at 1 part — so a run could end with N
       partial summaries and no whole one, or with an extra message, depending on a
       control the user could not see. Asked-for and forced splits are now distinct:
       asking for one part means asking for one summary, so the merge is not
       optional there, and the reason for the split is stated in the popup before
       the run and in the status line after it.
    
    Q  The paste retry fired when the text had not been SEEN to land within 15 s,
       which is not the same as it not being there. A slow editor got a second copy
       stacked under the first: one message carrying the prompt and the whole
       transcript twice. It now re-checks, then clears, before re-pasting.
    
    R  A payload was kept for a reload whenever the send could not be confirmed,
       including when the text was already in the composer and had probably gone
       out. Any provider tab opened within 5 minutes then replayed the whole
       sequence. Kept now only when nothing reached the editor, and for one retry.
    
    S  pendingLLMContent is one key for the whole browser, so the next video in a
       web batch overwrites it. A chat tab still booting claimed the wrong video's
       transcript and reported it under the wrong job. A payload written after this
       document started belongs to a tab that has not opened yet; the abandoned job
       is now closed honestly instead of sitting on "Sending" forever.
    
    T  A failed paste consumed its pasteWatch entry, so the retry the status line
       tells the user to make could never correct the verdict. The entry now leaves
       on success only.
    
    Tests: 240 assertions across 11 suites, up from 140 across 6. Every one of the
    nine fix points is mutation-verified: the bug put back, the test required to go
    red. ytsClearInput is verified on real editors in Chrome 150 and Firefox 153
    via test/e2e/clear-retry, each case carrying a control that proves the doubling
    is real without it.
    
    ROADMAP.md: the two gaps against comparable tools that are worth closing — no
    fallback for videos without captions, and subtitle search plus per-chapter
    summaries — with sources and how each would be built here.
    
    test/e2e/upload-probe.mjs: attaching the transcript as a file instead of typing
    it was re-measured after Gemini's composer redesign, which is the condition
    NOTES 4.4 leaves that question open on. Still no file input anywhere, shadow
    roots included, and a synthetic drop produces no chip; the assignment mechanism
    itself works, so the probe is kept for the next redesign.
